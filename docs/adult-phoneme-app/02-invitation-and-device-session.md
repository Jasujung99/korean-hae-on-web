# 개인 초대와 기기 이어하기

## 확정된 진입 방식

`교사가 학습자 등록 → 개인 초대 전달 → 첫 기기 연결 → 공통 학습 주소에서 이어하기`

매번 초대 링크를 발급하지 않는다. 학습자는 처음 한 번 개인 초대로 연결하고, 기기 세션이 유효한 동안 같은 학습 주소에서 이어간다. 기록은 고정된 `learner_id`에 저장한다.

MVP에는 개인 초대·기기 기억·같은 학습자에게 재발급을 넣는다. 공용 QR은 공통 주소로 들어가는 입구로 쓸 수 있다. 공용 QR+개인 참여 코드, 이메일 인증번호, 소셜 로그인, 로그인된 기기에서 연결 코드 발급은 후속 기능이다.

## 화면과 행동

| 화면 | 보이는 내용 | 다음 행동 |
|---|---|---|
| 교사 학습자 추가 | 별칭, 반, 선택형 모어·주사용 언어 | 저장하고 최초 초대 만들기 |
| 교사 목록 | 별칭, 초대 상태, 마지막 학습, 관찰할 기록, 재발급 | 링크 복사 또는 상세 관찰 |
| 개인 초대 첫 방문 | “알렉세이 님의 연습입니다”, 브라우저 안내 | 명시적으로 ‘이 기기에서 시작하기’ |
| 연결 성공 | 연결된 별칭과 연습 진입 | 초대 토큰 없는 공통 학습 주소로 이동 |
| 공통 주소 재방문 | “알렉세이 님, 이어서 연습해요” | 저장된 진행에서 듣기 퀴즈 |
| 연결 없는 공통 주소 | 교사에게 받은 개인 링크로 시작하라는 안내 | 교사에게 새 초대 요청. 별칭만으로 본인 연결하지 않음 |
| 만료·사용·폐기된 초대 | 사용할 수 없다는 공통 안내 | 교사에게 재발급 요청 |
| 새 기기 | 새 초대로 동일 학습자 연결 | 기존 이력을 이어서 표시 |
| 공용 기기 | 현재 연결된 별칭, ‘이 기기에서 나가기’ | 현재 기기 세션만 종료 |

최초 화면에는 다른 학습자 목록·이메일·반 전체 정보를 노출하지 않는다. 별칭이 본인과 다르면 시작하지 않고 교사에게 문의할 수 있게 한다.

## 초대 링크의 상태와 보안 경계

권장 경로는 `/join#token=…`다. URL 조각의 토큰을 클라이언트가 읽고 현재 기록에서 제거한 뒤 메모리에만 보관한다. 연결은 사용자의 명시적 버튼으로 요청한다. 실제 라우터에 맞춘 세부 경로는 변경할 수 있으나 다음 동작은 유지한다.

1. **GET·페이지 미리보기로는 초대를 소비하지 않는다.** 메신저 링크 미리보기 봇·보안 스캐너가 주소를 열어도 연결 상태가 바뀌지 않는다.
2. 화면 확인은 필요한 최소 별칭만 반환하는 읽기 요청이다. 성공적인 확인 요청도 토큰을 소비하지 않는다.
3. ‘이 기기에서 시작하기’의 `POST`에서 유효성 확인·소비·기기 세션 발급을 원자적으로 처리한다.
4. 초대 원문 대신 서버 비밀값을 이용한 해시/HMAC를 저장한다. 충분한 엔트로피의 암호학적 난수 토큰을 사용한다.
5. 사용 후 만료·폐기하며 같은 링크로 다른 기기가 다시 연결되지 않는다. 재시도 처리를 위한 멱등 키는 별도로 쓴다.
6. 초대 토큰·세션 토큰은 URL 로그, 분석 도구, 오류 수집, DB 일반 로그에 남기지 않는다.

초대는 소지자에게 연결 권한을 주는 bearer credential이다. 최초 링크가 실제 수강생에게 갔는지는 교사의 전달 과정에 의존한다. 확인 화면의 별칭 선택을 강한 본인 인증으로 설명하지 않는다.

### 시작 정책값

초대 유효기간 72시간, 기기 세션 최대 30일을 기본 제안값으로 두고 서버 설정으로 관리한다. 확정된 사용자 요구는 ‘초대의 일회성’과 ‘재방문 기기 기억’이며 기간 숫자는 운영 전에 조정할 수 있다. 만료·폐기·권한 변경을 서버에서 검사하며, 클라이언트 시계에 의존하지 않는다.

## 기기 세션

새 성인 웹앱의 같은 origin 서버 API가 세션을 발급한다. 브라우저에는 불투명한 기기 세션 식별자를 `HttpOnly; Secure; SameSite=Lax; Path=/` 쿠키로 둔다. 운영에서는 `__Host-` 접두사를 사용할 수 있다. JS가 세션 토큰을 읽거나 localStorage에 복사하지 않는다. 로컬 HTTP 개발용 쿠키 설정은 운영 설정과 구분한다.

서버의 세션에는 해시, `learner_id`, 생성·만료·폐기 시각, 마지막 사용, 최소 기기 설명을 남긴다. 세션은 서버 조회로 학습자를 정한다. API 본문으로 받은 `learner_id`를 믿고 다른 사람의 기록을 저장하지 않는다.

쿠키 사용만으로 CSRF 보호가 끝나지는 않는다. 상태 변경 요청은 same-origin, Origin 검사와 CSRF 방어, 허용된 JSON 요청을 적용한다. CORS를 `*`로 열지 않는다. 다른 origin 서버를 선택한다면 쿠키·CSRF·CORS 설계를 ADR에서 다시 검토한다.

기기 기억은 같은 브라우저 프로필의 저장 상태에 의존한다. 메신저 내 브라우저, Chrome, Safari, 시크릿 모드, 쿠키 삭제는 별개일 수 있다. 첫 화면에는 ‘계속 사용할 브라우저에서 열기’를 짧게 안내한다. 외부 브라우저 전환은 초대 소비 전에 하도록 한다.

## 재발급과 다른 기기

교사는 기존 `learner_id`의 상세에서 재발급한다. 새 학습자를 만들거나 기존 응답을 복제하지 않는다.

- 새 초대를 만들면 같은 학습자의 미사용 이전 초대를 폐기한다.
- 일반 재발급은 기존 정상 기기 세션을 자동 삭제하지 않는다. 여러 기기 사용을 허용한다.
- 잘못 연결됐거나 링크가 유출됐다면 ‘기존 기기 연결도 해제’ 옵션을 별도 확인 후 실행한다. 해제 대상과 결과를 화면에 표시한다.
- 세션을 해제해도 학습 이력은 남긴다. 별칭을 바꿔도 ID와 이력은 유지한다.
- 한 브라우저는 동시에 한 학습자만 활성 연결한다. 다른 학습자의 초대는 기존 연결의 교체 확인 후 처리한다.

만료된 링크를 열었다는 이유로 무한 재발급하거나 이메일을 자동 발송하지 않는다. 교사가 평소 쓰는 메신저로 전달한다. 앱이 메신저·메일을 자동 발송하는 기능은 MVP 범위 밖이다.

## 이어하기와 미전송 기록

서버의 마지막 진행과 미완료 문항을 기준으로 이어간다. 초대 URL 자체를 즐겨찾기 주소로 안내하지 않는다. 연결 후에는 토큰 없는 공통 주소를 안내한다.

미전송 이벤트는 학습자·회기·문항 판에 묶인 로컬 outbox에 넣고 같은 이벤트 ID로 재전송한다. 세션이 만료되거나 다른 학습자로 연결되면 전송을 멈춘다. 이전 큐를 새 학습자 ID로 바꿔 보내지 않는다. 서버도 현재 세션과 원래 회기의 소유자가 같은지 확인한다.

나가기 전에 미전송 기록이 있으면 동기화 상태를 보여준다. 오프라인에서 기기 연결을 지우면 아직 보내지 못한 기록이 사라질 수 있음을 확인하고 처리한다. 로그아웃은 현재 기기 세션과 해당 기기의 개인정보를 정리하며 서버에 저장된 전체 학습 이력을 삭제하지 않는다.

## 교사 인증

교사는 기존 Supabase Auth 계정을 재사용할 수 있으나 성인용 `teacher` 역할과 담당 학습자 배정이 있어야 한다. 기존 어린이 앱의 `admin`이라는 이유만으로 성인 기록 전체에 접근하지 못한다. 도메인이 다르면 기존 로그인 상태의 자동 공유는 보장하지 않는다.

시안의 ‘학습자 / 교사 관찰’ 전환은 리뷰용이다. 실제 서비스에서는 교사 인증과 권한 확인을 거쳐 별도 관찰 경로에 들어간다.
