# 다른 개발 모델에 전달할 지시문

아래 지시문을 저장소와 함께 전달한다. 구현 시작 전에 이 문서 묶음을 읽고, 실제 저장소 상태를 확인한다.

```text
Jasujung99/korean-hae-on-web의 docs/adult-phoneme-app 문서 묶음을 기준으로
성인 한국어 소리 학습 앱의 개발 1~6단계를 구현해줘.

읽는 순서:
README.md
01-decisions-and-content-plan.md
02-invitation-and-device-session.md
03-implementation-stages.md
04-data-and-api-contracts.md
05-acceptance-and-release.md
prototypes/README.md와 PC/모바일 시안

개발 1~6단계와 학습 Stage 0~5는 다른 개념이야.
목표는 학습자가 링크로 연결되어 연습을 이어가고,
교사가 기록을 관찰하는 기능을 로컬/검토 환경에서 끝까지 구현하는 것이야.
Core 60 승인과 다화자 전이 효과를 구현만으로 완료했다고 보고하지 마.

처음에 브랜치, git status, AGENTS.md, README, package/lockfile,
배포 workflow, 실행 환경을 확인해. 기존 수정은 보존하고 전용 브랜치에서 작업해.
기존 본사이트의 빌드 상태를 먼저 기록해.

현재 본사이트는 Astro 정적 앱이야. 성인 앱은 별도 apps/learn 패키지로 구성하고
현재 본사이트·루트 배포를 유지해. 프레임워크/서버 런타임은 실제 환경을 보고
개발 1단계에서 선택 근거와 실행 명령을 ADR로 기록해.
old-site, old-design-system, 루트 index.html을 현재 디자인 기준으로 쓰지 마.

디자인은 src/design-system의 현재 해온 문법을 따라.
종이색 바탕, 올리브색, 명조, 실제 로고, 세이지·라벤더, 여백을 적용해.
design-preview 폴더는 학습 구성용 참조이며 디자인 서식의 기준이 아니야.

학습자는 개인 초대로 첫 연결한 뒤 같은 공통 주소에서 이어가.
이력은 고정 learner ID에 저장해. 초대는 일회용이며 명시적 시작 POST로만 소비해.
메신저 미리보기 GET/inspect로 소비하지 마. 새 기기는 같은 learner에 재발급해.
기기 세션은 서버에서 검증하고 HttpOnly 쿠키를 사용해.
learn.haeonkorean.com은 제안 주소이므로 아직 DNS나 운영 주소를 바꾸지 마.

모어별로 코스를 쪼개지 말고 공통 커리큘럼을 사용해.
첫 6문항으로 음향 원인을 진단하거나 언어권별 유형을 자동 확정하지 마.
기본은 균형 출제, 이후 실제 응답 표본에 따라 조절하고 정책 판을 기록해.
자음 식별, ABX, 뜻 확인, 첫 제출, 재시도를 각각 기록해.

기존 Boa_newwords Supabase를 공동 사용하는 설계야.
성인 phoneme_* 역할·배정·API·데이터를 추가하되 기존 어린이 테이블/정책/역할 함수를
바꾸지 마. 접두사만으로 보안 격리가 됐다고 판단하지 마.
로컬 마이그레이션·RLS·API 접근 시험을 먼저 준비해.
운영 프로젝트에 reset/seed/마이그레이션을 직접 실행하지 마.

대표 기본 TTS 음성 하나를 사전 생성·검수해 고정 파일로 재생해.
맞춤 목소리 설계·복제·실시간 생성은 초기 범위 밖이야.
키는 GEMINI_API_KEY 환경 변수에서만 읽고 로그/코드/문서/브라우저에 노출하지 마.
키·권한·할당량이 없으면 해당 실제 연결만 미완료로 남기고 독립 작업은 계속해.
빌드와 테스트에서 실제 생성 호출을 하지 마.
음원이 없으면 무음 fixture를 실제 듣기 성적으로 저장하지 마.

교사는 담당 수강생의 활동시간·선택 오류·재청취·중단/재개를 관찰해.
채점·피드백 작성과 콘텐츠 운영 UI를 필수로 추가하지 마.
시안의 역할 전환 버튼은 리뷰용이고 실제 교사 인증을 대체하지 않아.

단계별로 의미 있는 검증을 하고 끝까지 진행해.
필수 외부 권한 때문에 못한 항목은 구체적으로 남겨.
운영 DB 적용, DNS, 운영 배포, main 병합은 사용자 확인 전 실행하지 마.
마지막에는 단계별 완료 상태, 파일 diff, 실행 명령과 검증 결과,
실제 연결과 fixture의 구분, 미완료 항목과 사용자 작업을 한국어로 보고해.
```

## 구현 모델이 먼저 남길 계획

개발 단계별 파일 위치, 선택한 앱/서버 구조, 마이그레이션 실행 대상, 현재 가능한 검증을 짧게 기록한다. 계획 보고만 하고 멈추지 말고 이미 허용된 구현·검증을 계속한다. 운영 변경의 승인 요청은 구체적인 결과와 diff를 준비한 뒤 마지막에 한다.
