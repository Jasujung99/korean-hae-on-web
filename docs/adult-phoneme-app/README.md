# 성인 한국어 소리 학습 앱 개발 인계

기준일: 2026년 11월 16일 · 개발 전 상세 지시서

교사가 아는 성인 수강생에게 개인 초대 링크를 전달하고, 학습자는 첫 연결 뒤 같은 학습 주소에서 이어서 연습한다. 교사는 기록을 보고 수업에서 피드백한다. 첫 기능은 ㅈ·ㅊ·ㅉ 듣기 퀴즈이며, 사전·예문·어휘로 확장한다.

이 묶음은 다른 개발 모델이 **개발 1~6단계까지 구현**할 때의 기준이다. 학습 커리큘럼의 **Stage 0~5는 별개의 콘텐츠 분류**다. 개발 6단계 완료가 Core 60 승인이나 다화자 전이 검증까지 뜻하지 않는다.

## 읽는 순서

1. [설계 결정과 콘텐츠 제작 계획](01-decisions-and-content-plan.md): 확정 결정, 공통 커리큘럼, 검수·TTS·공동 Supabase 경계.
2. [개인 초대와 기기 이어하기](02-invitation-and-device-session.md): 첫 연결, 재방문, 새 기기, 만료·재발급.
3. [개발 1~6단계](03-implementation-stages.md): 단계별 산출물·완료 조건·작업 범위.
4. [데이터와 API 계약](04-data-and-api-contracts.md): 콘텐츠 판, 교사 배정, 초대·세션, 이벤트.
5. [검증과 운영 적용 조건](05-acceptance-and-release.md): 접근·동시성·기록·회귀 시험과 운영 적용 절차.
6. [다른 모델에 전달할 프롬프트](06-model-handoff-prompt.md): 작업 시작용 지시문과 완료 보고 형식.
7. [최종 PC·모바일 시안](prototypes/README.md): 독립 실행 HTML과 편집용 원본.
8. [인계 묶음 검증과 현재 상태](07-validation-and-status.md): 이번 문서·시안 검증과 실제 구현 전 상태.

## 확정된 방향

- 개인 초대 링크로 학습자와 기기를 처음 연결하고, 이후 공통 주소에서 바로 이어간다.
- 기록의 소유자는 고정된 학습자 ID다. 링크·별칭·기기를 바꿔도 같은 이력을 유지한다.
- 로그인 비밀번호·이메일 인증·소셜 로그인을 학습자 MVP의 필수 단계로 넣지 않는다.
- 모어별 코스를 만들지 않고 공통 커리큘럼 안에서 관찰된 응답에 따라 출제 비중을 조절한다.
- 대표 TTS 기본 목소리 한 개로 시작한다. 음원은 사전 생성·검수·버전 고정한다.
- 기존 Boa_newwords Supabase를 공동 사용하되, 성인용 권한·API·데이터를 분리한다.
- 교사 관찰과 콘텐츠 운영을 구분한다. 콘텐츠 운영 UI는 초기 범위 밖이다.
- 디자인은 해온 웹사이트의 현재 [디자인 시스템](../../src/design-system/README.md)과 [토큰](../../src/design-system/tokens.css)을 따른다.

## 저장소와 구현 경계

확인한 `korean-hae-on-web`의 기준 커밋은 `d2938208e586bb500f0e43d39241b06e09ac53db`다. 현재 배포 앱은 Astro 정적 사이트다. 루트 `index.html`, `old-site/`, `old-design-system/`을 새 앱의 기준으로 사용하지 않는다.

새 학습 앱은 기존 본사이트와 분리된 패키지 `apps/learn/`에 구현하는 구조를 기본으로 한다. 기존 루트 앱을 통째로 변환하거나 기존 배포 명령이 학습 앱까지 배포하도록 바꾸지 않는다. 앱의 세부 프레임워크·실행 명령·서버 런타임은 개발 1단계에서 실제 환경을 확인하고 짧은 ADR로 기록한다. Boa_newwords의 React 기반 패턴을 참고할 수 있지만 어린이용 계정·페이지·데이터는 옮기지 않는다.

`learn.haeonkorean.com`은 제안 주소다. 확정 도메인·DNS·배포 대상은 운영 적용 전에 정한다. 개발 중에는 `LEARN_APP_ORIGIN` 같은 설정으로 주입하며 제안 주소가 활성화됐다고 표시하지 않는다.

## 자료의 권위와 충돌 처리

최근 사용자 결정과 이 묶음의 확정 결정 → 해온의 현재 디자인 시스템 → 이 묶음의 API·완료 조건 → 시안의 화면 배치 → 기존 PR의 참고 제안 순서로 적용한다. 시안은 설계용 예시이며 인증이나 실제 점수 구현의 원본이 아니다.

[Boa_newwords PR #2](https://github.com/Jasujung99/Boa_newwords/pull/2)는 커리큘럼 입력 자료다. 이 묶음은 해당 PR의 별도 Supabase·다화자 필수·음향 그래프 필수 제안을 현재 MVP에 맞게 조정한다. 연구별 수치나 모어별 처방을 검증된 제품 규칙으로 복사하지 않는다.

## 현재 산출물의 상태

이 묶음에는 개발 지시서와 시안만 있다. 실제 초대·인증·DB·음원 재생·관찰 API는 구현되어 있지 않다. 시안의 역할 전환 버튼과 예시 학습 기록을 운영 권한 체계로 사용하지 않는다.

기본 목표는 개발 6단계의 로컬·검토 환경까지다. 운영 DB 적용, DNS 변경, 운영 배포, `main` 병합은 구현 결과를 검토한 뒤 별도 사용자 확인을 받는다.
