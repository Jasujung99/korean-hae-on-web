# 검증과 운영 적용 조건

## 개발 단계의 검증

아래 표는 실제 인증·DB·음원이 연결된 기능의 통과 조건이다. fixture나 시안에서만 확인한 항목은 실제 연결 성공으로 표시하지 않는다.

| 영역 | 필수 사례 | 기대 결과 |
|---|---|---|
| 초대 미리보기 | 메신저 미리보기 봇·GET·inspect | 초대 미소비, 세션 미발급 |
| 최초 연결 | 유효 개인 초대에서 명시적 시작 | 같은 learner ID에 기기 연결, 토큰 없는 주소로 이동 |
| 동시 claim | 두 기기가 같은 초대를 동시에 사용 | 한 연결만 성공, 두 번째 기기 신규 연결 차단 |
| 요청 재시도 | claim 응답 유실 후 멱등 재시도 | 중복 학습자·세션 없이 안전한 결과 복구 |
| 사용·만료·폐기 | 해당 링크 재사용 | 연결 차단과 재발급 안내 |
| 재방문 | 공통 주소·공용 QR, 유효 기기 | 동일 학습자와 진행으로 이어짐 |
| 연결 없음 | 새 브라우저·쿠키 삭제 | 별칭만으로 연결하지 않고 개인 초대 요청 안내 |
| 재발급 | 기존 learner에 새 초대 | 이전 미사용 링크 폐기, 기존 기록 유지 |
| 기기 해제 | 특정 세션만 폐기 | 해당 기기만 차단, 다른 정상 기기·이력 유지 |
| 다른 학습자 연결 | 동일 브라우저의 기존 연결 교체 | 교체 확인, 이전 이벤트를 새 learner로 보내지 않음 |
| 교사 배정 | 다른 반·미배정 교사의 조회 | RLS와 API 모두 차단 |
| 기존 사용자 | 어린이 앱 인증 토큰으로 성인 조회 | 성인 역할·배정 없으면 비공개 기록 차단 |
| 콘텐츠 상태 | draft 의미·음원·문항 공개 요청 | 학습자에 노출·출제되지 않음 |
| 정답 보호 | 제출 전 current 응답 | 정답·서버용 필드 미노출 |
| 이벤트 중복 | 같은 이벤트/응답 재전송 | 한 번만 기록, 내용 충돌은 오류 |
| 중단과 복귀 | 새로고침·네트워크 끊김·다음 접속 | 서버 진행과 미전송 상태를 조정해 이어짐 |
| 음원 오류 | 로드·재생 실패·무음 fixture | 일반 오답에서 제외, 오류와 다음 행동 표시 |
| 과제 분리 | 식별·ABX·뜻 확인·재시도 | 각각 집계, 첫 제출 유지 |
| 판 교체 | 새 의미·음원·릴리스 게시 | 과거 응답은 당시 판 참조, 신규 출제만 새 판 |
| 시간 | 숨김·긴 무응답·재청취 | 시간 정의 일치, 중복 합산 방지 |
| UI | PC·320px 모바일·키보드·터치 | 주요 조작 가림/잘림 없음, 로딩·오류·빈 상태 제공 |

쿠키 발급·권한·초대 동시성·이벤트 중복은 서버/DB를 포함한 통합 시험으로 확인한다. 화면 조건문을 그대로 반복하는 테스트만으로 대체하지 않는다. 키 없이 수행할 시험과 실제 음원·인증이 필요한 시험을 구분한다.

## 기존 서비스 회귀

현재 Astro 본사이트의 루트 빌드와 경로, 해온 디자인 자산, 기존 `deploy` 배포 구조를 확인한다. 성인 앱 패키지의 설치·빌드가 루트 정적 앱을 깨뜨리지 않아야 한다.

Supabase 변경은 먼저 로컬/검토 환경에서 검증한다. 기존 보호자 로그인·자녀 프로필·받아쓰기·오답·기존 관리자 기능이 유지되는지 확인한다. 전체 DB reset, 기존 역할 함수 권한 확대, 원본 seed 재적재로 해결하지 않는다.

기존 프로젝트의 현재 테이블·RLS·함수·Auth 설정·Storage·사용량·백업 상태는 운영 적용 전에 읽기 전용으로 확인한다. 로컬 마이그레이션 파일만으로 운영 상태와 같다고 보고하지 않는다.

## 운영 반영의 경계

개발 6단계의 목표는 로컬·검토 환경에서 기능과 검증을 완료하고 운영 적용안을 검토 가능하게 만드는 것이다. 운영 DB 마이그레이션, 새 앱 배포, DNS, 도메인 등록, main 병합은 자동 진행하지 않는다.

운영 적용안에는 아래 내용을 구체적으로 담고 사용자 확인을 받는다.

1. 실제 배포 도메인과 서버 런타임, 기존 본사이트와의 경계.
2. 신규 마이그레이션의 정확한 diff, 백업·복원 방법, 적용 전후 권한 검사.
3. 승인 릴리스와 실제 생성·검수한 음원 수, 미준비 Stage.
4. Auth 리디렉션·쿠키·Origin 설정과 기존 앱 영향.
5. 도메인/DNS의 변경 전 값과 적용할 최소 변경.
6. 정상·오류 상황의 모니터링, 재발급·기기 해제 절차.
7. 문제가 생겼을 때 성인 앱 연결과 신규 출제를 중단하고 직전 릴리스로 되돌리는 절차.

공동 DB의 롤백에서 성인 학습 기록을 즉시 삭제하지 않는다. 앱 비활성화·초대 발급 중지·릴리스 전환을 우선 준비한다. 이미 저장된 데이터가 있으면 마이그레이션 down/drop은 별도 검토한다.

## 완료 보고 양식

각 단계는 `완료 / 부분 완료 / 미완료`로 표시하고 아래를 기록한다.

- 기준 브랜치·커밋, 기존 변경 보존 여부, 실행 환경.
- 바뀐 파일과 동작, 검증 명령·결과.
- 실제 Supabase/TTS 연결, 로컬 DB, fixture 중 사용한 환경.
- 승인 콘텐츠 수와 실제 음원 검수 여부.
- 미완료 조건·필요한 사용자 작업과 다음 단계.
- 운영 변경·병합·배포 실행 여부.

‘화면이 보인다’, ‘모델이 한국어를 지원한다’, ‘학습자가 많이 맞혔다’만으로 인증·음원 품질·교육 효과 검증을 완료했다고 표시하지 않는다.
