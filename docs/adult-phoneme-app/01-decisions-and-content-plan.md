# 성인 한국어 소리 학습 서비스 설계 결정과 콘텐츠 제작 계획

기준일: 2026년 11월 16일 · 설계 결정 v2 · 운영 적용 전

성인 학습자가 링크로 들어와 ㅈ·ㅊ·ㅉ 듣기 퀴즈를 연습하고, 교사는 활동과 오류를 관찰한다. 공통 커리큘럼 안에서 실제 응답에 따라 연습 비중을 조절한다. 첫 구현은 대표 TTS 음성으로 시작하며, 사전·예문·어휘 학습은 같은 콘텐츠 구조 위에 확장한다.

백엔드는 **기존 Boa_newwords의 Supabase 프로젝트를 공동 사용하는 방향**으로 정한다. 성인용 웹앱·권한·데이터는 분리하고, 기존 어린이 서비스에 영향을 주지 않는 접근 시험을 운영 적용 조건으로 둔다.

이 문서의 ‘잠금’은 설계 결정을 동결한다는 뜻이다. 학습자의 화면을 정답률로 강제 잠그는 정책과는 구분한다. 미승인 뜻·예문·음원은 출제되지 않게 하는 콘텐츠 승인 게이트를 별도로 둔다.

## 1. 설계에서 잠그는 결정

| ID | 확정할 결정 | 적용 내용 |
|---|---|---|
| D01 | 주 대상과 목표 | 외국어로 한국어를 배우는 성인. ㅈ·ㅊ·ㅉ 소리 식별 연습부터 시작한다. |
| D02 | 첫 화면 | 소개 단계를 필수로 거치지 않고 듣기 퀴즈로 진입한다. 재방문은 진행 중인 문항을 이어간다. |
| D03 | 공통 커리큘럼 | Stage 0~5의 분류와 기본 순서를 공통으로 쓴다. 모어별 별도 단어장·단계 트리는 만들지 않는다. |
| D04 | 개인화의 근거 | 제시 소리→첫 선택, 위치, 후행 모음 맥락, 재청취 기록으로 연습 비중을 조절한다. 모어는 선택형 배경 정보다. |
| D05 | 과제의 구분 | 자음 식별, ABX 비교, 어휘 뜻 확인을 각각 기록한다. 하나의 종합 정답률로 합치지 않는다. |
| D06 | 교사의 역할 | 담당 학습자의 학습 시간·활동·오답·재청취·중단/재개를 관찰한다. 채점·코멘트 작성은 필수 업무로 두지 않는다. |
| D07 | 콘텐츠 원본 | 원본 어휘와 추출 기록을 보존한다. 성인용 뜻·예문·발음·음원은 승인본과 버전으로 관리한다. |
| D08 | 음원 방식 | Gemini TTS 기본 목소리 중 대표 음성 1개를 골라 사전 생성·검수·고정 배포한다. 맞춤 목소리 설계는 초기 범위에서 제외한다. |
| D09 | 백엔드 | 기존 Supabase 공동 사용. 성인용 `phoneme_*` 데이터·권한·API를 추가하고 기존 어린이 테이블·정책·역할 함수는 유지한다. |
| D10 | 확장 구조 | 사전·예문·내 단어, 다른 자음 묶음은 동일한 어휘·의미·발음 출현·문항 구조에 추가한다. |
| D11 | 화면 디자인 | 해온 웹사이트의 현재 `src/design-system`을 따른다. 지정 `design-preview` 폴더는 학습 콘텐츠와 화면 구성의 참고다. |
| D12 | 콘텐츠 운영 화면 | 초기 사용자 화면에서는 제외한다. 검수는 문서·구조화 파일로 수행하고 승인 상태를 출제 게이트에 연결한다. |
| D13 | 개인 초대와 기기 기억 | 개인 초대로 최초 연결한 뒤 같은 공통 주소에서 이어간다. 초대는 명시적 사용 후 만료하고, 새 기기는 같은 학습자 ID에 재발급한다. |

개인 초대·기기 기억·재발급의 상세 계약은 [개인 초대와 기기 이어하기](02-invitation-and-device-session.md)를 따른다. 공용 QR은 공통 주소의 입구이며, 이메일·소셜 로그인·개인 참여 코드는 후속 확장이다.

잠금 결정의 변경은 사유·영향·변경 날짜를 남겨 다음 설계 버전으로 올린다. 아래의 파일럿 조정값은 이 잠금 대상에 포함하지 않는다.

## 3. 공통 학습 커리큘럼

| 단계 | 공통 콘텐츠 | 주된 활동 | 공개 조건 |
|---|---|---|---|
| Stage 0 | 모음 사이, 어두 ㅣ·ㅜ, 어두 ㅏ의 짧은 표본 | 피드백을 주지 않는 첫 듣기 점검 | 개별 6문항은 간단 점검. 여러 폼과 후속 공통 문항 전체에서 맥락×자음 균형 유지 |
| Stage 1 | 모음 사이 VCV. 1-A는 ㅈ과 다른 소리, 1-B는 ㅊ·ㅉ 비교 | 듣고 세 소리 중 고르기. 필요하면 ABX 도움 | 의사단어와 기준 단어의 발음·음원 검수 |
| Stage 2 | 비음 ㄴ·ㅁ·ㅇ 뒤, 어중 연쇄 | 위치를 넓힌 자음 식별 | 단어에 여러 목표 자음이 있으면 출제 위치를 명시 |
| Stage 3 | 어두 ㅣ·ㅜ 맥락, 자연스러운 구에서 단독 단어로 연결 | 어두 자음 식별, 비교 피드백 | 구·단어 각각 자연스러운 음원과 정확한 목표 위치 |
| Stage 4 | 어두 ㅏ·ㅓ·ㅗ 맥락 | 어두 자음 식별, 모음 맥락을 섞은 복습 | 음원별 실제 소리 확인. 고정 F0 차이를 정답 규칙으로 강요하지 않음 |
| Stage 5 | 새 음성 전이와 표기·발음 차이 | 전이 점검과 음운 변동 활동을 각각 수행 | 훈련에 쓰지 않은 승인 음성 및 검수된 변동 어휘 |

Stage는 콘텐츠 분류다. Stage 하나를 접속 한 번이나 고정된 4~5분과 일치시키지 않는다. 반복 횟수와 하루 분량은 실제 소요 시간에 맞춰 조정한다. 새로운 단계는 필요한 콘텐츠가 승인됐을 때 공개하며, 단일 정답률만으로 학습자를 앞 단계에 가두지 않는다.

공통 순서는 콘텐츠를 함께 관리하기 위한 제품 결정이다. 모든 모어 화자가 반드시 동일한 음향 기제와 습득 순서를 거친다는 주장으로 사용하지 않는다. 어두 학습의 단서를 F0 하나로 줄이지 않으며, PR의 특정 실험에서 유의한 차이가 없었다는 결과도 두 범주의 완전한 동등성을 입증한 것으로 해석하지 않는다.

### 첫 듣기 점검과 평가

6문항은 가볍게 시작하기 위한 선택이다. PR의 고정 예시 6문항에는 맥락별로 빠진 자음이 있으므로, 고정된 6개를 모든 학습자에게 반복 사용하지 않는다. 여러 균형형 폼을 만들고 이후 공통 문항에서 관찰을 누적한다.

‘ㅈ을 ㅊ으로 골랐다’는 기록만으로 F0 과잉 의존, 유성음 대입, 폐쇄 길이 둔감 같은 음향적 원인을 확정할 수 없다. 화면에는 관찰한 선택과 문항 수를 표시한다. 3지선다의 무작위 선택 기준은 1/3이며, 다른 선택지 수의 연구에서 나온 우연 수준을 그대로 적용하지 않는다.

학습 전후를 비교할 때는 같은 맥락·과제·난이도로 맞춘 평가 블록을 따로 마련한다. 훈련에서 반복한 음원을 다시 맞힌 결과와 새 음성에서의 전이는 별도다. Stage 0과 Stage 5의 서로 다른 문항 정답률을 단순히 빼서 학습 효과라고 보고하지 않는다.

### 한 번의 연습 흐름

`듣기 퀴즈 → 첫 선택 확인 → 정답 소리와 내 선택 비교 → 다음 문항 → 짧은 연습 마무리`

ABX 도움을 열면 현재 문항을 보존하고 돌아올 수 있게 한다. ABX의 응답은 자음 식별 첫 제출에 섞지 않는다. 뜻·예문은 퀴즈를 마친 뒤 선택해서 살펴보는 확장 경로로 둔다.

아자·아차·아짜나 자음 글자 선택지를 보여주는 과제는 ‘듣고 자음 고르기’다. 글자 범주를 사용하지 않는 ABX와 구분하며 ‘철자 없는 순수 청각 변별’로 표시하지 않는다.

## 4. 오류 기반 개인화

### 고정할 원칙

개인화의 단위는 **정답 소리 → 선택 소리 × 실제 발음 위치 × 후행 모음 맥락 × 과제**다. 예를 들어 `어두 /ㅏ/에서 ㅈ→ㅊ 선택`과 `모음 사이에서 ㅉ→ㅈ 선택`은 다른 기록이다. 단어 난도·음원 판·화자도 함께 남긴다.

모어·일상 주사용 언어는 선택 입력이다. ‘중국어권=A형’, ‘러시아어권=B형’ 같은 자동 라벨이나 모어만을 근거로 한 힌트 강제 노출은 하지 않는다. 초기에 자료가 적으면 균형 문항을 먼저 제공한다.

### 파일럿에서 조정할 초깃값

다음 값은 구현을 구체화하기 위한 초안이며 교육적으로 검증된 기준이 아니다.

| 설정 | 시작 제안 | 조정할 근거 |
|---|---|---|
| 한 연습 분량 | 10~12문항 | 실제 활동 시간, 중단, 피로·반복 반응 |
| 12문항 구성 | 공통 기본 6 + 취약 후보 3 + 간격 복습 3 | 아직 취약 후보를 고를 자료가 없으면 균형 문항으로 채움 |
| 취약 후보 활성화 | 동일 위치·모음 맥락에서 누적 12문항 이상, 자음별 최소 4문항 | 표본 수와 서로 다른 문항 수를 함께 보고 과도한 쏠림 점검 |
| 가중치 | 기본 1.0, 취약 후보에 최대 1.5를 시험 | 1.5는 연구 효과량이나 확정값이 아님. 공통 문항 비율을 유지 |
| 반복 제한 | 같은 문항 판은 연습 안에서 최대 2회 | 음원·위치만 외우는 반복 방지. 피드백 재생과 채점 재시도는 별도 |
| 선택 변경 | 첫 제출 전 변경 가능 | 제출 후 재시도는 첫 응답을 덮어쓰지 않음 |

최소 문항 수를 채웠다고 신뢰성 높은 진단이 완성되는 것은 아니다. 서로 다른 문항·어휘에서 같은 현상이 반복되는지 함께 확인한다. 힌트가 있는 연습과 힌트 없는 점검도 구분해서 기록한다.

선택 정책은 `selection_policy_version`과 실제 추출 확률·출제 사유를 남긴다. 교사 화면의 비교에는 학습자가 서로 다른 문항 비중을 받았다는 점이 반영되어야 한다. 학습량이 늘어도 같은 공통 평가 블록은 유지한다.

## 5. 콘텐츠를 만드는 단위와 순서

### 원본부터 릴리스까지

`원본 스냅샷 → 자음 후보 추출 → 의미 대조 → 성인용 뜻·예문 → 발음 출현 확인 → TTS 생성 → 청취 검수 → 문항 판 → 승인 릴리스`

원본에는 오류도 그대로 남긴다. 수정은 새 학습용 버전으로 만들고 `ERROR_FIX`와 `ADULT_ADAPT`를 구분한다. 공개 API로 가져왔다는 사실이나 기존 검수 칸이 비어 있다는 사실은 정확성 승인으로 간주하지 않는다.

| 콘텐츠 단위 | 꼭 남길 정보 | 필요한 이유 |
|---|---|---|
| 원본 항목 | `source_commit`, 경로·해시, `inventory_id`, `entry_id`, `lexeme_key`, 원본 rank | 추출 재현과 원본 추적. rank와 운영 DB id를 혼동하지 않음 |
| 의미 단위 | 표제어, 품사, 한자·원어, 동형어, 사전명·뜻 ID·조회일 | 같은 표기의 다른 뜻이 연결되는 오류 방지 |
| 학습용 판 | 뜻·예문, 수정 사유, 출처·이용 조건, 검수자·시각, 버전 | 성인용 각색과 오류 수정을 설명하고 교체할 수 있음 |
| 발음 출현 | 표기 자음·실제 소리, 음절 위치, 어두/어중, 앞 소리, 후행 모음, 변동·근거 | 단어에 여러 자음이 있거나 표기와 소리가 다를 때 정확히 출제 |
| 음원 판 | 모델·목소리·입력문·설정, 생성일, 파일 해시·길이·형식, 검수 상태 | 어떤 소리를 들었는지 재현하고 교체 전후 기록을 보존 |
| 문항 판 | 과제·목표 출현 ID·음원 ID·보기·정답·힌트·난도 태그 | 과제 간 성적 구분과 정확한 출제 |
| 릴리스 | 승인된 어휘·음원·문항 판의 ID 묶음과 게시일 | 학습 중 자료가 바뀌지 않는 배포 단위 |

한 단어의 발음 위치를 단어 행 하나의 단일 태그로 고정하지 않는다. `주차장`처럼 목표 소리가 여러 번 나오는 단어는 출현별로 나누고 문항이 어느 소리를 묻는지 지정한다. 음절 번호는 1부터 표시하되 데이터의 문자 인덱스는 기존 추출 규약인 0부터 유지한다.

### Core 60과 첫 검수 묶음

Core 60은 공통 목표 집합이다. 표제어만 60개 나열하는 대신 **표제어+의미 단위로 확정한 목록**을 만들고, 단계 연결은 다대다로 둔다. 같은 의미가 여러 Stage에 쓰여도 단어 수를 중복해서 세지 않는다. ㅈ·ㅊ·ㅉ의 후보 수 차이는 출제 비율로 조정하며 부적절한 단어를 억지로 채워 수를 맞추지 않는다.

첫 공개 파일럿은 아래 **12개 후보**의 뜻·예문·발음·음원 검수를 먼저 끝낸다. 이 목록은 DB 입력용 승인 데이터가 아니다.

| 목표 소리 | Stage 1 우선 후보 | 선택 의도 |
|---|---|---|
| ㅈ | 모자, 바지, 어제, 의자 | 생활 장면으로 연결하기 쉬운 모음 사이 출현 |
| ㅊ | 기차, 아침, 고치다, 가르치다 | 이동·일상·행동에 쓰이는 모음 사이 출현 |
| ㅉ | 가짜, 이쪽, 그쪽, 여쭈다 | 실제 생활에서 쓸 수 있는 ㅉ. 지시어·높임말 용법도 함께 확인 |

이후 감자·편지·산책·근처·진짜·공짜 등 Stage 2 후보를 검수해 초기 집합을 18개 안팎으로 넓히고, Stage 3~5 후보를 더해 Core 60을 완성한다. 적합한 ㅉ 어휘가 부족하면 승인된 의사단어로 소리 연습량을 확보한다. 의사단어를 사전 표제어로 등록하지 않는다.

PR의 예시 목록도 다음을 정리한 뒤 가져온다.

- `김치찌개`는 4음절이다. ‘3음절’이 목표 ㅉ의 위치라면 ‘세 번째 음절 찌’로 명시한다.
- `조금씩`을 ㅉ 표제어 예시로 자동 편입하지 않는다. 정확한 목표 소리와 발음 위치를 다시 확인한다.
- `이 지금` 같은 연결용 구를 자연스러운 생활 표현으로 검토한다. 음향 환경을 만들기 위한 부자연스러운 문장을 학습 예문으로 내보내지 않는다.
- `지금`·`차`·`모자`·`사장`·`사진`·`화장실` 등 알려진 의미 연결 오류는 새 목록에서도 회귀 검수 항목으로 둔다.

### 뜻과 예문 검수

1. 원본의 한자·원어·품사와 현재 사전의 해당 의미를 대조한다. 사전 번호가 같다는 이유만으로 연결을 승인하지 않는다.
2. 잘못 연결된 뜻은 올바른 의미 ID로 재연결하고 근거를 남긴다. 의미를 확인하지 못하면 보류한다.
3. 성인용 풀이는 쉬운 한국어로 작성하고, 번역은 초기 필수값으로 두지 않는다.
4. 예문은 성인이 쓸 만한 장면 하나에서 목표 의미가 분명하게 드러나도록 쓴다. 새 예문은 사람이 작성하거나 작성 보조 후 검수하며, 사전 인용과 구분한다.
5. 발음·뜻·예문의 자연스러움과 출처·재사용 조건을 확인한 뒤 승인한다. 출처 불명의 기존 예문은 승인 전 배포하지 않는다.

검수 초안 예시는 `모자: 머리에 쓰는 물건 / 햇빛이 강해서 모자를 썼어요.`다. 이런 문안도 초안 상태에서 시작한다. API 원본, AI 생성문, 사람 수정문을 서로 구분해서 보관한다.

### 발음 검수

표기와 실제 소리를 분리한다. 받침 중화, 연음, 된소리, 격음화, 구개음화는 표기 검색만으로 승인하지 않는다. 발음 사전이나 사람이 확인한 근거를 남긴다. 예외가 있는 규칙은 자동 규칙 결과를 검수 후보로만 쓴다.

후행 모음의 실제 값을 저장한다. PR의 `high_i_u`, `low_a_eo_o`는 커리큘럼 묶음 이름으로 쓰되, ㅗ 등을 엄밀한 음성학적 저모음이라고 일괄 설명하지 않는다. 화면에는 필요한 경우 `ㅣ·ㅜ 맥락`, `ㅏ·ㅓ·ㅗ 맥락`처럼 모음을 직접 쓴다.

Stage 1의 모음 사이 ㅈ이 모든 음원에서 같은 정도로 유성음화된다고 약속하지 않는다. 연구 평균 F0 차이나 VOT 수치를 TTS의 목표값으로 지정하지 않는다. 실제 음원에서 확인하지 않은 그래프는 ‘실측’으로 표시하지 않는다.

## 6. 콘텐츠 승인과 교체 규칙

| 상태 | 허용되는 작업 | 학습자에게 공개 |
|---|---|---|
| candidate | 추출·분류 | 불가 |
| draft | 뜻·예문·발음·음원 제작 | 불가 |
| needs_review | 오류·모호함 확인 및 재검수 | 불가 |
| approved | 검수 통과, 릴리스 편입 가능 | 릴리스에 편입한 범위만 가능 |
| retired | 신규 출제 중단, 과거 기록 참조 | 신규 출제 불가 |

콘텐츠 운영 화면이 없어도 구조화된 검수 파일에 상태·사유·검수자·시각을 기록한다. 누락 상태는 `unreviewed`로 해석한다.

음원만 쓰는 자음 식별 문항은 발음·음원·문항 승인이 필요하다. 뜻 확인과 사전 카드는 의미·예문 승인도 필요하다. 연결 단어 카드가 미승인이면 퀴즈 결과에 노출하지 않는다.

뜻·예문을 바꾸면 학습용 판을 새로 만든다. 읽을 글이나 발음이 달라졌다면 음원도 다시 생성·검수한다. 모델·목소리를 바꾸면 새 음원 판과 릴리스로 올린다. 기존 문항의 파일을 같은 경로에 덮어쓰지 않는다.

오류가 발견된 판은 즉시 신규 출제에서 내리고, 영향받은 응답에는 분석 제외 사유를 남긴다. 학습자의 원시 응답을 고쳐서 정답으로 만들지는 않는다. 과거 기록은 당시 판을 계속 참조한다.

## 7. 대표 TTS 음성으로 시작하는 방법

### 가능 여부

**Gemini API로 한국어 학습용 음원을 만드는 것은 공식 문서상 가능하다.** `gemini-3.8-flash-tts`와 `gemini-3.8-flash-lite-tts`가 제공되며 한국어를 지원한다. 현재 안내된 `generateContent` 방식과 `voiceConfig.voice`도 유효하다. [Google TTS 가이드](https://ai.google.dev/gemini-api/docs/speech-generation), [Flash TTS 모델](https://aistudio.google.com/docs/models/gemini-3.8-flash-tts)

| 항목 | 이번 결정 |
|---|---|
| 음성 | 운영용 대표 기본 목소리 1개. `Iapetus`를 첫 청취 후보로 두되, 실제 ID 확정은 표본 검수 뒤에 한다. |
| 모델 | 첫 품질 확인은 Flash TTS. 대량 생성에서 Lite 사용 여부는 같은 검수 기준으로 비교한 뒤 정한다. |
| 말투 | 기본 설정을 우선 사용한다. 과장된 조음·성문 긴장·고정 음높이를 지시하지 않는다. |
| 생성 단위 | 의사단어·실제 단어·예문을 각각 짧은 파일로 만든다. 긴 원고의 문자 수 분할 규칙은 초기 앱에 필요하지 않다. |
| 재생 | 학습 중에는 승인된 파일을 재생한다. 재생할 때마다 실시간 TTS를 생성하지 않는다. |
| 검수 | 의도한 소리가 맞는지, 자연스러운지, 잘림·잡음·다른 글 낭독이 없는지 확인한다. |
| 범위 | 맞춤 목소리 생성·복제·세밀한 음성 디자인은 초기 범위 밖이다. |

대표 목소리가 한국어를 지원한다는 사실과 ㅈ·ㅊ·ㅉ를 학습용으로 충분히 구별해 생성한다는 판단은 다르다. 의사단어가 실제 단어나 다른 소리로 교정되어 읽히는지도 확인한다. ASR 전사 일치만으로 음소 구별을 승인하지 않는다.

첫 제작은 대표 음성으로 VCV 9개(`아자/아차/아짜`, `이자/이차/이짜`, `오자/오차/오짜`)와 소수 기준 단어를 확인하는 순서다. 후보 음원은 정답을 보지 않고 한국어 청자가 듣는 방식으로 검사하고, 헷갈리는 파일은 보류한다. 본격 공개용 대립 문항은 별도의 청자가 한 번 더 확인한다.

청취 검수를 통과한 뒤 12개 기준 단어와 예문을 만든다. 초기 예상 작업량은 의사단어 9개 + 단어 12개 + 예문 12개 = **33개 텍스트 단위**다. 재생성본·추가 토큰·다화자 파일은 이 수에 포함되지 않는다. 같은 원본 파일을 ABX 기준음과 정답음으로 반복 사용해 파형 기억만으로 맞힐 수 있게 만들지 않는다. ABX 공개에는 승인된 서로 다른 토큰을 준비한다.

대표 음성 한 개로는 새 화자 일반화를 확인할 수 없다. 다화자 훈련과 별도로 보관한 평가 음성이 준비되어야 Stage 5의 ‘새 음성 전이’를 연다. 그전에는 같은 음성에서 다른 문항·단어로 넓힌 연습으로 표시한다.

같은 목소리 ID에서 새로 만든 파일은 ‘새 토큰’이다. 새 화자 전이에는 훈련에서 쓰지 않은 다른 목소리 ID의 승인 음원을 사용하며, 합성 목소리 사이의 전이가 실제 사람 화자 전이까지 입증하는 것은 아니다.

### API와 파일 처리

사용자가 제시한 `POST /v1beta/models/{model}:generateContent`를 첫 검증 경로로 유지할 수 있다. 새 문서의 Interactions API와는 요청·응답 스키마를 섞지 않는다. 기본 목소리를 사용하면 `POST /voices`나 저장된 맞춤 목소리 목록을 먼저 조회할 필요가 없다.

키 값은 `GEMINI_API_KEY` 환경 변수에서 읽는다. 서버 또는 로컬 제작 과정에서만 사용하고 프런트엔드 번들·문서·URL·로그에 넣지 않는다. 초기 검증에는 `temperature`를 생략하고, 말투 지시도 필요할 때만 추가한다.

3.8 비스트리밍 기본 출력은 WAV다. 응답 MIME과 컨테이너를 확인해 그대로 저장한다. RIFF가 아니라는 이유만으로 무조건 PCM이라고 간주해 헤더를 붙이지 않는다. 재생용 압축본은 검수한 원본에서 만들고, 자음의 폐쇄·마찰·기식 구간을 변형하는 손질은 하지 않는다. [모델 출력 형식](https://aistudio.google.com/docs/models/gemini-3.8-flash-tts#migration-guide)

429는 서버의 재시도 안내를 우선 따르고 횟수 상한을 둔 지수 백오프를 쓴다. 30초 고정 대기를 모든 경우의 정답으로 삼지 않는다. 잘린 응답·빈 오디오·형식 불일치는 승인하지 않고 제작 오류로 남긴다.

### 이번 환경에서 확인한 범위

- 공식 API·모델 문서와 한국어 지원을 확인했다. 음성 생성 요청은 보내지 않았다.
- 현재 실행 환경의 `GEMINI_API_KEY`는 설정되어 있지 않다.
- 사용자 지정 I: 키 파일 경로는 읽기 접근이 되지 않았다. 키 내용은 열거나 출력하지 않았다.
- `multi-agent-skills-lab` 프로젝트의 실제 권한·결제·할당량·저장된 목소리는 확인하지 않았다.
- 다음 연결 점검은 사용자가 키를 로컬 환경 변수로 설정한 뒤 `GET /v1beta/models/{model}`로 시작한다. 메타데이터 조회 성공도 실제 생성 할당량과 발음 품질까지 증명하지는 않는다. [Models API](https://ai.google.dev/api/models)

따라서 판정은 **‘기술적으로 가능, 해당 프로젝트 실호출과 학습용 품질은 미확인’**이다. 이 문서에 실제 키나 계정 비밀값은 포함하지 않는다.

### 공동 사용 조건

`phoneme_`는 이름 구분이다. 데이터 접근은 별도 성인 역할·교사 배정·RLS·GRANT·서버 검증으로 제한한다. RLS를 우회하는 서버용 관리자 클라이언트를 쓰는 경로도 요청마다 담당 교사·학습자·릴리스 범위를 확인한다. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)

| 영역 | 설계 경계 |
|---|---|
| 기존 어린이 서비스 | 기존 6개 테이블, 정책, 역할 enum·함수, 자녀 소유권 구조를 성인 서비스 때문에 바꾸지 않음 |
| 성인 교사 | 기존 `auth.users` 계정은 재사용 가능. 성인 전용 역할과 담당 학습자 배정이 있어야 조회 가능 |
| 링크 학습자 | 긴 무작위 토큰으로 진입. 서버에는 토큰 해시·만료·폐기를 저장. 성인 API가 학습자 범위를 검증 |
| 승인 콘텐츠 | 게시된 릴리스의 문항과 필요한 승인 자료만 제공 |
| 초안·학습 기록 | 익명 전체 읽기 금지. 기존 vocabulary 공개 정책을 복사하지 않음 |
| 음원 Storage | `phoneme-audio` 버킷을 설계. 초안과 승인 경로의 읽기 권한을 구분. 버킷은 현재 존재한다고 확인되지 않음 |

개념상 필요한 데이터 묶음은 다음과 같다. 물리 테이블과 DDL은 다음 구현 설계에서 확정한다.

| 묶음 | 예정 엔터티 |
|---|---|
| 어휘·콘텐츠 | `phoneme_lexemes`, 학습용 버전, 발음 출현 |
| 음원·출제 | `phoneme_audio_assets`, 문항 판, 승인 릴리스 |
| 학습자·권한 | `phoneme_learners`, 교사 역할·배정, 링크·기기 세션 |
| 학습 기록 | 학습 회기, 멱등 응답 이벤트, 재계산 가능한 집계 |

`vocabulary.id` 연결은 원본 참조로 사용할 수 있지만, 함께 원본 스냅샷·의미 키·커밋·해시를 남긴다. 기존 원본 삭제가 성인 학습 기록의 연쇄 삭제로 이어지지 않게 한다. 운영 id와 seed rank를 같은 값으로 연결하지 않는다.

공동 DB는 Auth·자원·운영 장애 범위도 공유한다. 기존 계정 삭제가 성인 역할·기록에 미치는 영향, Auth 메일·리디렉션 설정 변경이 두 앱에 미치는 영향을 검토한다. 향후 분리는 데이터뿐 아니라 Auth·Storage·권한·FK·세션 이관이 필요하므로 ‘몇 분 안에 분리’로 약속하지 않는다.

### 비용·용량 설명의 보정

확인일 현재 Free는 활성 프로젝트 2개와 파일 Storage 1GB를 안내한다. Pro는 조직 요금이 월 $25부터이고 추가 프로젝트는 월 $10부터이므로, ‘프로젝트마다 무조건 $25’라는 설명은 수정한다. 공동 사용도 사용량 증가에 따라 비용이 달라질 수 있다. [공식 요금](https://supabase.com/pricing), [Billing FAQ](https://supabase.com/docs/guides/platform/billing-faq)

Free의 일시 정지는 약 1주간 낮은 DB 활동에 따른다. 앱 페이지를 열었다는 사실만으로 DB 활동이 발생하는 것은 아니고, 공동 사용이 항상 정지를 막는다는 보장도 없다. [일시 정지 안내](https://supabase.com/kb/faqs/platform/free-project-pausing)

음원 용량은 단어 수만으로 확정하지 않는다. 24kHz·16비트·모노 PCM의 계산상 크기는 초당 약 48,000바이트다. 평균 5초 파일 1,000개라면 헤더 제외 약 240MB다. 압축 형식·재생성 원본·화자·예문·배포 트래픽을 합해 추산하고 실제 운영 사용량을 확인한다.

## 9. 교사 관찰과 기록

목록에는 최근 학습, 활동 시간, 학습한 날, 반복 선택, 재청취와 중단/재개를 보여준다. 개인 상세에서는 과제·소리 위치·모음 맥락을 고르고 첫 제출과 피드백 후 재시도를 각각 본다. PC는 목록과 상세를 함께, 모바일은 목록에서 상세로 들어간다.

시간은 전체 경과, 화면이 보이고 활동이 있던 시간, 실제 음원 재생, 화면 이탈·무응답을 구분한다. 음원 재생 시간은 활동 시간과 겹칠 수 있으므로 전부 더해 총시간처럼 표시하지 않는다. 응답 대기는 자극이 끝난 뒤부터 첫 응답까지로 정의하고, 중간 재청취·화면 숨김을 함께 남긴다.

긴 체류는 관찰 신호다. 집중도, 학습 곤란, 음향 단서 의존 유형으로 자동 판정하지 않는다. 6문항 첫 점검과 작은 표본은 그 수를 표시한다. 비교 화면에는 같은 평가 조건의 기록을 우선 사용한다.

원시 이벤트는 `event_id`, 회기 순번, `item_version_id`, `release_id`, `audio_id`, 첫/재시도 구분, 선택, 재생·시간·오류 상태를 가진다. 재전송 중복을 제거하고, 음원 교체 후에도 당시 판을 찾을 수 있어야 한다.

## 10. 구현과 공개의 순서

1. **결정 기준 유지**: 이 문서를 기준으로 공통 코스·응답 기반 개인화·대표 TTS·공동 Supabase의 경계를 고정한다. PR #2의 별도 DB·다화자 필수·그래프 필수 제안은 변경 이력으로 연결한다.
2. **12개 후보의 의미 확정**: 사전 의미를 대조하고 성인용 뜻·예문 초안을 검수한다. 실패 항목은 다른 후보로 대체한다.
3. **TTS 연결 가능성 점검**: 로컬 환경 변수로 키를 준비하고 모델 메타데이터·프로젝트 권한을 확인한다. 생성 전에 대표 음성의 짧은 표본 작업 범위를 정한다.
4. **소리 표본 검수**: 승인된 작은 음원 집합에서 ㅈ·ㅊ·ㅉ의 구별과 의사단어 발음을 확인한다. 대표 음성을 선택한다.
5. **구조화 콘텐츠와 보안 설계**: 버전·승인·교사 배정·링크 세션·RLS·Storage 정책을 마이그레이션 초안과 접근 시험으로 준비한다.
6. **듣기 퀴즈와 관찰 연결**: Stage 1부터 진행·응답·재청취·중단/재개를 연결한다. 초기에는 균형 출제를 사용하고 관찰이 쌓인 뒤 조절 규칙을 켠다.
7. **기존 서비스 회귀 확인**: 기존 계정·자녀·받아쓰기·관리 기능이 유지되는지 확인한 뒤 성인 모듈 운영 적용을 검토한다.
8. **공개 범위 확대**: 검수된 Stage 2~4, 사전·예문, Core 60을 순차 공개한다. 다화자와 별도 평가 음원이 준비되면 Stage 5 전이를 공개한다.

공개 전 통과 조건은 다음과 같다.

- 활성 문항이 모두 승인된 콘텐츠·음원 판을 참조한다.
- 음원 재생 실패·미재생·중도 응답·미응답을 일반 오답과 구분한다.
- 익명·다른 교사·기존 어린이 앱 계정이 성인 비공개 기록을 읽지 못한다.
- 링크 폐기·세션 재개·중복 전송에서 기록 범위와 횟수가 유지된다.
- 뜻·예문 교체와 음원 교체 후 과거 기록의 참조가 유지된다.
- 키가 브라우저·저장소·문서·로그에 노출되지 않는다.
